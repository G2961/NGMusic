Важно: **hover-кадр — это НЕ оранжевая звезда, это светло-серое кольцо без
заливки**, а не то что можно было бы интуитивно предположить. Финальный
"voted"-кадр — оранжево-красный.

### CSS-правила (точная логика, файл css/votebar_rules_extracted.css)
/* Дефолт: тёмно-серая звезда (idle) */
div.vote-input div.star-bar, div.vote-input div.star-blam {
  background: url(star-select-2.webp) 0 -49.4769px / 55.3846px 245.908px repeat-x;
}

/* labels невидимы сами по себе, но накладывают :before */
div.vote-input div.star-bar input + label::before {
  content: ""; position: absolute; inset: 0;
}

/* При hover на КОНКРЕТНЫЙ input — весь бар (через label::before) красится
   в hover-кадр (светлое кольцо) */
div.vote-input div.star-bar input:hover + label::before,
div.vote-input div.star-bar label.hover::before {
  background: url(star-select-2.webp) 0 0px / 55.3846px 245.908px repeat-x;
}

/* При checked — весь бар красится в оранжевый checked-кадр */
div.vote-input div.star-bar input:checked + label {
  background: url(star-select-2.webp) 0 -98.9538px / 55.3846px 245.908px repeat-x;
}

/* Каждый label — своя доля ширины и свой z-index (меньшая оценка сверху) */
div.vote-input div.star-bar input[value="1"] + label { z-index: 15; width: 10%; }
div.vote-input div.star-bar input[value="2"] + label { z-index: 14; width: 20%; }
/* ... по нарастающей до */
div.vote-input div.star-bar input[value="10"] + label { z-index: 6; width: 100%; }
Итоговый видимый эффект: наводишь на "позицию где должна быть 4.5 звезда" →
физически это попадает в label[value=9] (т.к. 9/10 * 5 звёзд = 4.5 звезды
по счёту) → весь бар красится в hover-кадр, но обрезанный по ширине 90%
(width label'а) → визуально ты видишь 4 целые закрашенные звезды + половину
5-й закрашенной, остальное (правая половина 5-й звезды) остаётся в фоновом
tidy-состоянии позади. Так достигается "половинчатая" точность без реального
разрезания SVG звезды — это чистый width-clip через CSS box model.

### Реакция (Steve/NG-персонаж справа от звёзд, отдельный компонент)
Есть отдельный .star-reaction блок (Steve/тролль-лицо) со своим спрайтом
SteveReact4.webp (приложен) — 11 кадров (reaction-0 до reaction-10),
меняющих выражение лица персонажа в зависимости от текущей hover/checked
оценки (0 = нейтральное/грустное, 10 = максимально довольное). Это ОПЦИОНАЛЬНО
для реализации — если легко сделать, здорово, но не приоритет; если сложно
интегрировать — можно оставить как статичную иконку или пропустить.

## Что нужно реализовать в Flutter

Полный аналог этого поведения через GestureDetector/Slider-подобный
кастомный виджет (готового Flutter-виджета с такой логикой нет, пишется
кастомно):

1. Ряд из 6 "звёзд-слотов": первый слот — отдельная кнопка "0" (можно не
   реализовывать если 0 баллов не нужен как опция, либо сделать по аналогии),
   следующие 5 — единая горизонтальная область, поделённая на **10 равных
   вертикальных полос** (каждая полоса = пол-звезды).

2. Три визуальных состояния каждой звезды, вместо спрайта используй
   Material/кастомные drawable:
   - idle — Icon тёмно-серая звезда в кольце (можно Icons.star + серый
     цвет + Container с круглой рамкой, либо кастомный CustomPainter)
   - hover/press (во время onPanUpdate/onTapDown, ДО отпускания) —
     светлое кольцо БЕЗ заливки (не закрашенная звезда, а именно
     контур/обводка!)
   - checked/voted (финал) — оранжево-красный градиент заливка
     (LinearGradient от #FF8800 к #F62F36 — цвета из общей NG-палитры,
     см. NgColors если уже заведены в проекте)

3. Логика заполнения по ширине, не по целым звёздам: при
   onPanUpdate(details) вычисли localPosition.dx / totalWidth, преобразуй
   в диапазон 0..10 (шаг 0.5), и закрашивай **все звёзды до этой позиции
   целиком + последнюю звезду частично** (через ClipRect с
   widthFactor на слой поверх idle-звезды — ровно так же как на сайте это
   делает label::before с width: N*10% поверх общего фона).
   4. Три фазы взаимодействия (важно, подтверждено скринами пользователя):
   - До взаимодействия: все звёзды idle (тёмно-серые)
   - Во время зажатия/drag (палец ещё не отпущен): звёзды до выбранной
     позиции подсвечиваются в hover-кадр (светлое кольцо), показывая preview
     будущей оценки — это НЕ финальная отправка голоса, только визуальный
     feedback
   - После отпускания (onPanEnd/onTapUp): отправляется запрос
     голосования (аналог Voting... состояния из текущей реализации — можно
     оставить лоадер на этом шаге), и при успехе звёзды перекрашиваются в
     checked-кадр (оранжевый), плюс текст меняется на "You voted {N}!"
     (десятичное значение показывай как N/2 где N — число полу-шагов,
     т.е. voted=9 → "You voted 4.5!" — сверь с реальной механикой сайта,
     возможно там int, уточни по факту если завязано на существующий бэкенд)

5. Не трогай: логику самого HTTP-запроса на голосование (если уже
   реализована в проекте под старый UI — эндпоинт и параметры не меняются,
   меняется только визуальный слой виджета).
